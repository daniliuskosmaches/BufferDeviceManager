# BufferDeviceManager

## Windows: история Win+V (CLI)

Эта версия наблюдает за **списком истории Win+V**, а не только за текущим
содержимым буфера. Написана на Go, напрямую использует Windows Runtime API
`Clipboard.HistoryChanged` и `Clipboard.GetHistoryItemsAsync`. PowerShell и внешние Go-модули не нужны.

### Запуск

Требуются Windows x64 (Windows 10 версии 1809 или новее / Windows 11), Go 1.20 или новее,
а также включённая история буфера (**Win+V → Включить**).

Открыть терминал в распакованной папке проекта, где лежит `go.mod`:

```powershell
go run ./internal/clipboard
```

Или собрать отдельное приложение:

```powershell
go build -o clipboard-history.exe ./internal/clipboard
.\clipboard-history.exe
```

Остановка: **Ctrl+C**. На macOS Windows-реализация не запускается.

### События

При запуске существующие записи принимаются за исходное состояние; сообщения
о добавлении для них не печатаются. Дождитесь строки «История доступна».

| Изменение списка Win+V | Вывод |
| --- | --- |
| Новый текст или картинка появились в истории | `добавление` |
| Предыдущие записи сдвинулись ниже | Без дополнительных сообщений |
| Удалена любая старая запись | `удаление` |
| Очистка истории | Одно `удаление` на исчезнувшую запись |
| Только перестановка существующих ID | Без сообщений |
| Новая запись вытеснила старую при заполненной истории | `добавление`, затем `удаление` |

Закреплённые записи, оставшиеся после очистки, не считаются удалёнными.
Повторное копирование считается добавлением только если Windows создала новый ID.
Поддерживается любая запись, которую Windows сохранила в Win+V. Данные, которые
не попали в историю, не вызывают сообщение. Содержимое записей не читается,
не выводится и не передаётся по сети.

### Устройство и ограничения

Программа подписывается на `Clipboard.HistoryChanged` **до** получения исходного
списка. После уведомления Windows читает историю и сравнивает идентификаторы.
Без уведомлений список не запрашивается. `HistoryEnabledChanged` позволяет
реагировать на включение и выключение истории.

Для Windows Runtime создан внутренний DispatcherQueue на STA-потоке с обработкой
системных сообщений. Это не графическое окно: пользователь работает только с CLI.
Обработчики Windows лишь сигнализируют событие, а чтение выполняется вне callback.
Даже завершение асинхронного чтения ожидается через `Completed`, без опроса статуса.
При Ctrl+C снимаются подписки и завершается DispatcherQueue.

Периодических таймеров нет. Есть только защитные таймауты для уже начатого чтения
(3 секунды) и завершения DispatcherQueue (5 секунд); они не запускают проверки
истории по расписанию.

- `internal/clipboard/windows.go` — CLI и вывод.
- `internal/clipboard/history_windows.go` — чтение истории через Windows Runtime API.
- `internal/clipboard/events_windows.go` — подписки, COM-обработчики и ожидание событий.
- `internal/clipboard/events_windows_test.go` — Windows-тесты обработчиков и отмены ожидания.
- `internal/historydiff/diff.go` — сравнение снимков истории.
- `internal/historydiff/diff_test.go` — тесты сравнения.

Это **событийная подписка**, но не гарантированный журнал каждой промежуточной
записи: уведомление Windows сообщает об изменении истории, а не передаёт полный
список операций. Несколько уведомлений могут объединиться в одно обновление.
Запись, успевшая появиться и исчезнуть до чтения истории, может остаться незамеченной.
Программа не отличает ручное удаление от автоматического вытеснения Windows.
Обычная вставка Ctrl+V ничего из истории не удаляет.

Выключенная или недоступная история не считается пустым списком: программа
сообщает причину. Повторное чтение выполняется только при следующем уведомлении
Windows, без фоновых повторов по таймеру. При включении истории заново устанавливается
исходный снимок. При других временных ошибках сохраняется последний успешный снимок;
после восстановления показываются итоговые различия за перерыв. Если уведомлений
больше нет, для новой попытки можно перезапустить CLI.

### Проверка

```powershell
go test ./...
go build -o clipboard-history.exe ./internal/clipboard
```

Тесты сравнения работают и без Windows. Они проверяют добавления, удаление старой
записи, очистку, перестановку, одновременное добавление и вытеснение, несколько
новых записей и сохранение закреплённой записи.

Перед сдачей нужно проверить реальную Windows:

1. Включить историю и запустить CLI. Дождаться «История доступна».
2. Скопировать уникальный текст: одно «добавление».
3. Скопировать другой текст: ещё одно «добавление», без событий из-за сдвига старого.
4. Скопировать небольшую картинку и убедиться, что она появилась в Win+V:
   одно «добавление».
5. В Win+V удалить старую, не верхнюю запись: одно «удаление».
6. Закрепить запись и очистить остальные: сообщения только для исчезнувших.
7. Выключить историю в настройках Windows: сообщение о выключении без ложного
   массового «удаление». Включить заново: новый исходный снимок.
8. Нажать Ctrl+C: завершение.

Также проверить отсутствие лишних сообщений в простое, несколько быстрых
копирований и Ctrl+C во время ожидания. Завершить и запустить CLI несколько раз,
чтобы проверить снятие подписок и завершение DispatcherQueue. Проверка реального Win+V в среде
разработки не выполнялась: среда — Linux. Go-тесты и кросс-сборка не заменяют её.

Проверено в Linux с Go 1.25.1: `go test ./...` проходит;
`GOOS=windows GOARCH=amd64 go vet ./...` проходит;
кросс-сборка Windows x64 успешно создаёт исполняемый файл.
Windows-тесты обработчиков скомпилированы, но не запущены в Linux; выполнить
`go test ./...` на Windows x64. Они проверяют ссылки COM, уведомление до начала
ожидания и пробуждение по отмене, не читая и не изменяя пользовательский буфер.

## Linux Clipboard

На текущем этапе приложение работает с буфером обмена Linux через `wl-clipboard`.

### Требования

Установить `wl-clipboard`:

```bash
sudo pacman -S wl-clipboard
```

Для других дистрибутивов пакет называется `wl-clipboard` и устанавливается через их пакетный менеджер.

### Как это работает

Приложение периодически получает текущее содержимое буфера через:

```bash
wl-paste
```

Go-программа сравнивает текущее значение с предыдущим. Если содержимое изменилось, изменение фиксируется как новое событие.

Сейчас реализовано:

```text
Linux Clipboard
      ↓
   wl-paste
      ↓
 Go Clipboard Watcher
      ↓
обнаружение изменения
```

На следующем этапе изменение будет преобразовываться в сообщение и передаваться на другое устройство по сети.
