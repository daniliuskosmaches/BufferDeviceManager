# BufferSync для Android — простой прототип

Приложение на Java с одним экраном: подключение, поле текста, отправка, копирование
и внутренняя история последних 10 записей. Работает с **текстом и ссылками до 64 КБ**.
Изображения, файлы и синхронизация всей истории Win+V в эту версию не входят.

## Как попробовать после установки

1. На компьютере установить Go 1.20+ и открыть терминал в корне репозитория
   (рядом с `go.mod`). Запустить:

   ```sh
   go run ./cmd/clipboard-sync
   ```

2. В терминале появится ссылка `buffersync://…`. Компьютер и телефон должны быть
   в одной локальной сети. Передать ссылку на телефон, вставить в поле подключения
   и нажать **«Подключиться»**. Если ссылок несколько, выбрать IP Wi-Fi интерфейса.
   Разрешить входящее подключение TCP 7778 в системном брандмауэре для частной сети.
   Гостевая Wi-Fi сеть может запрещать связь между устройствами.
3. Написать текст в приложении → **«Отправить на устройства»** → на компьютере
   нажать **Ctrl+V** (на Mac — **Cmd+V**). Компьютер подтверждает отправку только
   после успешной записи в свой системный буфер.
4. Для обратной передачи оставить приложение активным на телефоне, скопировать
   новый текст на компьютере. Телефон получит его в историю и в системный буфер,
   если включено **«Копировать полученное»**.
5. Чтобы подключить второй телефон, вставить в него ту же ссылку. Компьютер служит
   общим узлом, поэтому должен оставаться включённым с запущенной программой.

Ссылка содержит секрет подключения. Не публиковать её и не коммитить.
Она даёт доступ к общему буферу всем, кто её получил. Перезапуск Go-программы
создаёт новую ссылку: старые подключения нужно настроить заново. Программа
не отправляет начальный буфер компьютера при старте; она ждёт его изменения.
Подключённое позже устройство получает последнее уже переданное значение.

Для проверки через Android Emulator можно явно показать адрес компьютера:

```sh
go run ./cmd/clipboard-sync -host 10.0.2.2
```

Если нужен только обмен между телефонами, без системного буфера компьютера:

```sh
go run ./cmd/clipboard-sync -memory
```

Этот режим работает и на Linux. Обычный режим нового компаньона поддерживает
Windows и macOS; существующая Linux-программа в `internal/clipboard` остаётся
отдельной частью проекта. Остановка компаньона — Ctrl+C.

## Что означает «автоматически» на Android

Android 10+ ограничивает чтение буфера: обычное приложение может читать его,
когда имеет фокус. Запущенная фоновая служба сама по себе не снимает ограничение.
Поэтому здесь используются публичный `ClipboardManager` и реальные события,
без root, AccessibilityService, имитации нажатий или специальных разрешений.

Есть три способа передать текст:

- Написать/вставить его в поле и нажать **«Отправить на устройства»**.
- В другом приложении выбрать **«Поделиться → BufferSync»**, затем отправить.
- Включить **«Автоотправка при открытии приложения»**, скопировать текст в другом
  приложении и вернуться в BufferSync. Доступный текст отправится при получении
  фокуса. По умолчанию автоотправка выключена.

При включённой автоотправке изменения буфера в активном окне обрабатывает
`OnPrimaryClipChangedListener`. Сетевые сообщения приходят сразу по запросу,
который сервер держит открытым до изменения (long polling). Таймаут 25 секунд
нужен для обновления сетевого соединения; это **не опрос буфера каждые 300 мс**.
На Windows компаньон подписывается на `WM_CLIPBOARDUPDATE`. Только дополнительный
вариант компаньона для macOS сравнивает буфер раз в секунду через `pbpaste`.

Когда приложение свёрнуто, Android может приостановить/закрыть процесс и сеть.
Постоянная фоновая синхронизация не обещается. Если текст успел прийти в фоне,
он сохраняется в памяти и копируется при возвращении в окно. При автоотправке
новое локальное копирование имеет приоритет над отложенным входящим текстом.
После потери связи нужно снова нажать «Подключиться».

## Внутренний буфер и границы прототипа

- История содержит до 10 уникальных записей. Нажатие на запись открывает её
  в поле текста; затем её можно скопировать или отправить.
- История работает без сети, но хранится только в памяти. Закрытие процесса
  или пересоздание экрана (например, поворот) очищает историю и отключает сеть.
  Поле текста и ссылка восстанавливаются при повороте; подключиться нужно снова.
- Очистка истории очищает список приложения. Она не удаляет системный буфер
  и записи на других устройствах.
- Синхронизируется последнее значение, а не журнал всех промежуточных операций.
  При быстрых изменениях промежуточные тексты могут объединяться. При одновременной
  отправке побеждает последняя запись, принятая компьютером.
- Внутреннее копирование полученного текста не отправляется назад по кругу.
  Саму ссылку `buffersync://` приложение не пересылает как текст.
- Автоматического поиска устройств, QR-кода, фоновой службы, передачи картинок,
  файлов и восстановления соединения пока нет.

## Файлы простыми словами

| Файл | За что отвечает |
| --- | --- |
| `app/src/main/java/dev/buffersync/MainActivity.java` | Экран, кнопки, история и события буфера телефона. Это точка входа Android-приложения. |
| `app/src/main/java/dev/buffersync/Pairing.java` | Проверяет ссылку: адрес компьютера, ключ и отпечаток сертификата. |
| `app/src/main/java/dev/buffersync/SyncClient.java` | Отправляет и получает текст по зашифрованному соединению, вне потока интерфейса. |
| `app/src/main/AndroidManifest.xml` | Объявляет приложение, доступ к сети и пункт меню «Поделиться». |
| `app/src/main/res/values/styles.xml` | Цвета и базовое оформление экрана. |
| `app/build.gradle`, `build.gradle`, `settings.gradle` | Настройки Android-проекта для человека, который будет собирать приложение. |
| `gradlew`, `gradlew.bat`, `gradle/wrapper/` | Запускают подходящую версию Gradle. |
| `../cmd/clipboard-sync/main.go` | Запускает программу на компьютере и печатает ссылку подключения. |
| `../internal/clipsync/server.go` | Общий буфер и доставка обновлений подключённым устройствам. |
| `../internal/clipsync/tls.go` | Создаёт ключ и сертификат для защищённого соединения. |
| `../internal/systemclipboard/` | Читает и записывает системный буфер Windows/macOS. |
| `app/src/test/`, `../internal/clipsync/server_test.go` | Проверки ссылок, размера текста, обмена и ошибок. |

Передача использует HTTPS с проверкой конкретного сертификата из ссылки
(certificate pinning), а запросы — случайный ключ. Сертификат и ключ создаются
при каждом старте; текст буфера не печатается в логи. Это собственный небольшой
протокол, **не совместимый с CrossPaste**. CrossPaste использован как пример идеи;
его исходный код и зависимости не копировались.

`GET /clipboard?check=1` проверяет подключение; `POST /clipboard` принимает UTF-8;
`GET /clipboard?after=N` ждёт новую ревизию и возвращает текст с `X-Revision`.
Все запросы требуют `Authorization: Bearer KEY`. Таймаут ожидания возвращает 204.
Максимум — 65536 байт UTF-8; пустой текст и NUL не поддержаны.

## Передача участнику, который делает сборку

Нужны JDK 17, Android SDK Platform 35, Build Tools 34.0.0.
В проекте зафиксированы Android Gradle Plugin 8.7.3 и Gradle 8.9.
Минимальная версия телефона — Android 8 (API 26), target SDK — 35.
В Android Studio: **Open → папка android → Gradle Sync**, затем выбрать устройство.

Если участник предпочитает терминал, из папки `android`:

```sh
./gradlew testDebugUnitTest assembleDebug
```

На Windows — `gradlew.bat testDebugUnitTest assembleDebug`.
APK появится в `app/build/outputs/apk/debug/app-debug.apk`.
Настройки локального SDK (`local.properties`) и результаты сборки не коммитить.

## Что проверено и что проверить на устройствах

Проверено при подготовке:

- `go test -race ./...` — тесты Go и конкурентного обмена проходят.
- Компаньон Go компилируется для Windows x64 и macOS ARM64.
- Все Java-классы компилируются с Android API 35; три JVM-теста проходят.
- Два настоящих Java-клиента обменялись Unicode-текстом через Go-сервер с TLS.
  Неверный ключ и неверный отпечаток сертификата отклонены.

APK не собирался и на реальном телефоне приложение не запускалось.
Компиляция Java не заменяет Android-сборку и проверку интерфейса. Gradle Wrapper
подготовлен; Gradle Sync Android-проекта в среде подготовки не подтверждён:
репозитории зависимостей не позволили загрузить AGP. Нужен доступ к Google Maven
и Maven Central на компьютере сборщика.

После сборки проверить:

1. Телефон → ПК: отправить кириллицу, эмодзи и несколько строк, вставить на ПК.
2. ПК → телефон: скопировать текст на ПК, вставить его на телефоне.
3. Два телефона: подключить оба, отправить текст с первого и получить на втором.
4. Включить автоотправку, скопировать в другом приложении, вернуться в BufferSync.
5. Проверить «Поделиться → BufferSync» и работу локальной истории без сети.
6. Свернуть приложение, отключить Wi-Fi, снова открыть: не должно быть ложного
   сообщения об успешной отправке; переподключиться после восстановления сети.
7. Повернуть экран, проверить отступы/клавиатуру на Android 15 и вручную восстановить
   подключение. Проверить, что копирование полученного не вызывает цикл отправок.
8. Перезапустить компаньон: старая ссылка отклоняется, новая работает.
